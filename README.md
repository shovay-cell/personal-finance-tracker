# FinTrack 💰
### Персональный и семейный трекер доходов и расходов с ИИ-сканированием чеков

Мобильное PWA-приложение (iOS / Android / браузер) для учёта доходов и расходов: распознавание чеков через Gemini, бюджеты и лимиты по категориям, плановые платежи, учёт выданных чеков на предъявителя и совместный семейный профиль на два устройства.

Все данные хранятся локально в IndexedDB. Наружу они уходят ровно в двух случаях: фото чека — в Gemini для распознавания и зашифрованный бэкап — в скрытую служебную папку вашего Google Drive.

---

## 🌟 Возможности

- 💸 **Операции**: расходы и доходы двумя табами, несколько счетов и кошельков с раздельным балансом, мультивалютность (₪ / $ / €) с фиксацией курса в момент операции, фото чека, метка автора.
- 🏷 **Категории**: 22 категории расходов и 5 доходов с подкатегориями. Свою категорию (иконка, цвет, родительская категория) можно завести прямо в форме операции — плитка «Создать» в сетке выбора; ненужные стандартные категории скрываются.
- 📷 **ИИ-сканирование чеков (Gemini)**: фото → дата, сумма, валюта, продавец, позиции и предполагаемая категория. Поля, в которых модель не уверена, подсвечиваются и **не сохраняются автоматически** — их подтверждает человек.
- 🎙 **Голосовой ввод**: «потратил 50 на кафе» → сумма, категория и дата подставляются в форму подтверждения. Русский, иврит, английский.
- ⚡ **Быстрый (sticky) ввод**: ярлыки на домашнем экране и плавающая «+» со шторкой — трата записывается за два касания.
- 🎯 **Бюджеты и лимиты**: общий месячный бюджет, лимиты по категориям, индивидуальные лимиты каждого из супругов, прогресс зелёный → жёлтый → красный, уведомления на 80% и 100%, перенос неизрасходованного остатка.
- 📅 **Плановые платежи**: разовые и регулярные (неделя / месяц / год / произвольный интервал), напоминание за N дней, автосоздание операции или подтверждение, отдельный блок просроченных.
- 🧾 **Чеки на предъявителя**: выданный чек создаёт открытое обязательство с остатком; подтверждающие документы прикладываются позже (тоже с распознаванием) и списывают сумму. Статусы: Выдан / Частично закрыт / Закрыт / Просрочен.
- 📊 **Отчёты**: разбивка по категориям за неделю / месяц / квартал / год / произвольный период (круговая диаграмма + таблица), динамика по месяцам, план/факт по бюджетам, отчёт по открытым обязательствам, экспорт CSV и PDF.
- 👨‍👩‍👧 **Семейный доступ**: один профиль на двух устройствах, код приглашения, роли (полный доступ / только просмотр), метка автора у каждой операции и в фильтрах, уведомления партнёру о крупных операциях.
- ☁️ **Бэкап Google Drive**: автоматически раз в сутки и вручную, в скрытую папку `appDataFolder`. Общая точка восстановления для обоих устройств, merge-синхронизация без потери офлайн-операций, плюс локальный файл `.fintrack`.
- 📱 **PWA и офлайн**: установка на домашний экран, работа без сети (ввод операций, отчёты — всё локально), поддержка «чёлки» и Safe Area.

## 🚀 Стек

- **Next.js 14** (App Router) + React 18 + TypeScript (strict)
- **Dexie.js** (IndexedDB) — локальная база
- **Tailwind CSS** + Lucide Icons
- **Gemini API** — мультимодальное распознавание чеков (серверный маршрут `/api/analyze-receipt`)
- **Google Identity Services + Drive REST API** (scope `drive.appdata`)
- **Web Speech API** — голосовой ввод (аудио в Gemini не отправляется)

Внешних зависимостей для графиков и PDF нет: диаграммы — инлайновый SVG, PDF — печать браузера (корректно печатает кириллицу и иврит системными шрифтами).

### Переменные окружения

Скопируйте `.env.example` в `.env.local` (файл в `.gitignore`, в репозиторий не попадает):

| Переменная | Назначение |
|---|---|
| `GEMINI_API_KEY` | Общий серверный ключ Gemini для распознавания чеков. **Только серверный** — префикс `NEXT_PUBLIC_` использовать нельзя, ключ попал бы в клиентский бандл. |
| `NEXT_PUBLIC_GOOGLE_CLIENT_ID` | Web OAuth Client ID из Google Cloud Console для бэкапа в Drive. Это публичный идентификатор, а не секрет. |

Обе переменные необязательны:

- без `GEMINI_API_KEY` каждый пользователь может вписать свой ключ в **Настройки → ИИ-сканирование чеков** (хранится только на его устройстве);
- без `NEXT_PUBLIC_GOOGLE_CLIENT_ID` Client ID вводится в **Настройки → Резервное копирование**.

Остальное приложение работает без каких-либо ключей — ручной ввод, бюджеты, отчёты и экспорт полностью локальны.

## 📱 Быстрый («липкий») ввод

1. **Ярлыки PWA** — долгое нажатие на иконку установленного приложения: «Добавить расход», «Сканировать чек», «Голосовой ввод». Ведут на `/?quick=expense|scan|voice` и сразу открывают нужный режим: камера и микрофон запускаются автоматически.
2. **Плавающая «+»** в нижней навигации — шторка с цифровой клавиатурой: сумма → категория → «Записать». Там же переключатели «Чек» и «Голос».

## 🗂 Структура

```

src/constants/categories.ts           категории, валюты, иконки, словари для голоса и чеков
src/lib/db.ts                         Dexie-схема, CRUD, конвертация валют, бэкап/восстановление/merge
src/services/analytics.ts             периоды, разбивки, бюджеты, обязательства, форматирование
src/services/planned.ts               периодичность, просрочка, материализация плановых платежей
src/services/notifications.ts         лимиты 80/100%, напоминания, крупные операции партнёра
src/services/export.ts                CSV и PDF
src/services/ai/receipt-parser.ts     сжатие фото, вызов Gemini, нормализация сумм/дат/валют
src/services/voice/voice-input.ts     Web Speech API + парсер фразы в операцию
src/services/backup/google-drive.ts   OAuth (Google Identity Services)
src/services/backup/drive-backup.ts   выгрузка, список, восстановление, merge-синхронизация
src/app/api/analyze-receipt/route.ts  серверный вызов Gemini
src/app/page.tsx                      экран приложения
src/components/*                      операции, бюджеты, планы, обязательства, отчёты, настройки
```

Доменный слой (`types`, `lib/db`, `services/*` кроме UI-зависимых) не зависит от React — при переносе на Flutter/React Native логика переписывается один в один.

## 🔐 Данные и приватность

- База — локальная (IndexedDB), сервер её не видит и не хранит.
- Фото чека уходит в Gemini только в момент нажатия «распознать»; на устройстве сохраняется сжатая копия, привязанная к операции.
- Бэкап пишется в `appDataFolder` — скрытую папку Drive, недоступную другим приложениям и не видимую в интерфейсе Drive.
- Ключ Gemini, введённый пользователем, и OAuth-токен хранятся только в `localStorage` устройства.

---

## 📌 Архитектурные решения

- **Синхронизация двух устройств — merge через общий бэкап Drive.** Реального времени без backend-компонента быть не может; вместо этого второе устройство подключает тот же Google-аккаунт, и записи сливаются по `updatedAt` — операции, добавленные офлайн, не теряются. Модель данных (участники, роли, метки автора, индивидуальные лимиты) готова к переносу на Firestore: меняется только транспорт в `services/backup/drive-backup.ts`.
- **Уведомления — Notification API, не FCM.** Push требует серверной подписки; локальные уведомления о лимитах, платежах и крупных операциях работают без backend. Каждое показывается один раз.
- **Курсы валют задаются вручную** и фиксируются в операции при сохранении, поэтому отчёты за прошлые периоды не «плывут» при изменении курса.
